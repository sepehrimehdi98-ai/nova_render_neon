# Teacher reference search, precise summaries and mobile navigation

The teacher main assistant and lesson-builder composer now offer the same opt-in public-reference search as the student assistant. It uses the existing free Python-documentation/Wikipedia retrieval policy, existing server capability checks, bounded caching and citation validation. Ordinary messages do not search automatically. File contents are not sent as search queries. The existing paid OpenRouter mode remains behind its explicit configuration gates; this change does not enable paid routing/search.

Teacher online conversation jobs and builder jobs persist `webSearch`. Retrieved web evidence joins selected file/link evidence. A web-grounded reply must cite a retrieved web source; failed or empty retrieval is disclosed. Source citations remain visible. Teacher conversation history retains its account/course access boundaries.

Summary instructions now prioritize exact facts, terms, conditions and relationships in the selected material/current lesson and agreed teacher discussion. Lesson summaries must be one summary-block operation, with specific learning points and a concrete learner practice tip. New web facts must not expand the lesson summary into unrelated material. Correct-option indices, sample solutions and private feedback/explanations are removed from the summary model context to reduce accidental answer disclosure. Existing teacher confirmation and explicit publication remain required. These are grounding/shape safeguards, not a mathematical guarantee of generated accuracy.

At widths below 1024px, teacher/admin application sidebars no longer reserve page width. The persistent header opens a labelled native-dialog menu with all role destinations. The teacher AI conversation list also opens from a separate history button. Drawers start closed, trap focus through native modal semantics, close by button/Escape/backdrop/link selection, and close when resized to desktop. Background scrolling is locked while open. Native dialog support is required. Course selection is retained in mobile navigation URLs.

Mobile content padding, form fields and touch targets are larger. Account names truncate within the header while avatars remain contained. Student navigation and desktop sidebar defaults are unchanged.

Validation: 62 automated tests plus autosave lifecycle checks pass. New backend checks verify opt-in search, web citations, summary single-operation validation, malformed flag rejection and absence of automatic lesson mutation. Typechecks, all portal builds, main build and component checks pass. The drawer render check verifies an initially closed, labelled dialog associated with its trigger. Browser screenshots, physical-device layout and native focus/touch interaction remain unverified because browser automation is unavailable.
