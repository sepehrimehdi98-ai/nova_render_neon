# Integrated panels and private lesson note safeguards

## Implementation
Current student/teacher/admin production builds include the preceding admin activity, course analysis, recovery, shared responsive and teacher video-source changes. Private lesson notes retain the current note visual treatment, with clearer save status, text export, retry, account-copy review and explicit conflict choices.

Notes remain plain text. They are never evaluated, rendered as HTML, used as SQL syntax, fetched as URLs or sent to AI by this feature. Server uses parameterized queries, authenticated owner+lesson scoping and published/enrolled lesson access. POSTs require the existing origin/session checks, an integer expected revision and <=10000 UTF-16 code units; invalid ASCII control characters are rejected. Whitespace, Persian, emoji, code and literal HTML-like text are preserved exactly. A committed per-user60/minute write budget includes rejected authenticated requests rather than being rolled back with a failed write.

Additive nova_lesson_note_revisions preserves a monotonic revision even for empty/deleted notes, preventing stale resurrection. Server locks the identity, rechecks revision and atomically writes note/revision; conflicts return409. GET returns body+revision. All callers of the lesson-note POST must send the revision; deploy frontend/backend together and refresh old tabs after upgrading.

The client keeps drafts in account+lesson-scoped browser keys, migrates old plain-text entries, reports quota/unavailable storage, retains edits when initial fetch or sync fails, avoids clearing new text typed during an in-flight save, and requires a deliberate choice on server conflicts. A text download provides an escape path. Dirty drafts warn before a full-page departure; browsers may suppress unload warnings, and SPA navigation does not universally invoke beforeunload. Cross-tab storage events warn of another change. The local draft store is not an encrypted vault or an atomic multi-tab database; same-origin scripts/browser users can access it. Do not promise local confidentiality on shared devices. Server note privacy does not grant teachers/admins access to another student's note.
