# Adaptive AI replies and Python prewarming

All existing AI entry points continue to use the same provider, role/course access checks, private sessions, file and link readers, opt-in web search, RAG indexing/retrieval, citation validation and proposal approval. Student model review and isolated code-example checks are retained. No paid routing is enabled and no verified answers are served from a shared response cache.

The provider receives guidance derived only from the actual user message: explicit English/Persian output language, brief/detailed preference, greeting detection and requested response purpose. The latest request and agreed conversation context take precedence. Ordinary replies aim for a direct, shorter explanation; explicit detailed requests and complete authoring remain supported. Greetings use a smaller token budget, brief answers use 1000, ordinary answers 1400, detailed answers 3000, lesson proposals 4000 and structured lesson summaries 1800. Token ceilings are not guaranteed response lengths or latency improvements.

Student public-reference retrieval and internal RAG retrieval run concurrently. Common public documentation links on docs.python.org, developer.mozilla.org and English/Persian Wikipedia can reuse a bounded two-minute in-memory fetch. Arbitrary hosts, query-bearing URLs, supplied test/custom dependencies and failures are not cached. Source fetching retains HTTPS/DNS/size/timeout checks. Cached public documents are not a cache of private files, conversations or generated answers.

For vague file requests without matching keywords, the existing three-section evidence budget now covers the beginning, middle and end rather than only the first sections. Specific questions retain keyword-ranked retrieval. Evidence carries page/total-page metadata and is explicitly labelled partial excerpts; the model must not claim that omitted pages were read. This improves coverage within the budget, not full-document reading.

The shared code runner can automatically prewarm one nearby Python box per page. Other boxes retain interaction-triggered warming. Automatic warming is skipped for data-saving connections and unsupported observer environments, and cancels on unmount. Existing per-box runtime reuse, fresh variables per run, standard input/output reset, stop button, output cap and 45-second execution timeout remain. This shifts cold initialization before the first click where possible; it does not reduce the Python runtime download size or guarantee startup speed.

Tests cover response guidance/provider payloads, authoring/review budgets, cache coalescing/expiry/privacy exclusions, file-section coverage and Python prewarm lifecycle, alongside the full platform regression suite. Read handoff evidence for actual timings, live generation outcomes, deployment delivery and any provider quota limitation. Browser automation is currently unavailable, so no new visual verification is claimed.
